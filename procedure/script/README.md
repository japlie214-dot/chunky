# procedure/script — Local helper scripts

Local Python scripts that run on your laptop. These are **NOT** Snowflake
procedures — they're standalone CLIs for getting data into and out of
Snowflake stages, and for regenerating the test fixtures.

## Scripts

### `upload_to_stage.py`

Upload a file (or every file in a directory) to a Snowflake stage
using browser-based SSO authentication. No stored credentials — the
Snowflake connector caches the SSO token in `~/.snowflake/` after
the first browser login.

**Why this exists:** The headless procedures in this repo expect
their input PDFs to already live on a Snowflake stage. The Snowflake
MCP server (`procedure/snowflake-mcp/`) is one way to put them there,
but it requires Claude Desktop. This script is the zero-dependency
alternative.

**Install:**
```bash
pip install snowflake-connector-python
```

**Usage:**
```bash
# Upload a single file
python3 procedure/script/upload_to_stage.py \
    --account myorg-myaccount \
    --user me@company.com \
    --stage @DEV_DB.DNA.DOCS \
    --file procedure/script/pdf/fy2024-tbk-investor-presentation.pdf

# Upload every PDF in a directory
python3 procedure/script/upload_to_stage.py \
    --account myorg-myaccount \
    --user me@company.com \
    --stage @DEV_DB.DNA.DOCS \
    --dir procedure/script/pdf/

# List what's already on the stage
python3 procedure/script/upload_to_stage.py \
    --account myorg-myaccount \
    --user me@company.com \
    --stage @DEV_DB.DNA.DOCS \
    --list
```

**Configuration:**
Account and user may also be supplied via environment variables or a
config file so you don't have to type them every time:

- Environment variables: `SNOWFLAKE_ACCOUNT`, `SNOWFLAKE_USER`,
  `SNOWFLAKE_ROLE`, `SNOWFLAKE_WAREHOUSE`
- Config file (`~/.chunky-upload.json` or path passed to `--config`):
  ```json
  {
    "account": "myorg-myaccount",
    "user": "me@company.com",
    "role": "IT_AI",
    "warehouse": "COMPUTE_WH"
  }
  ```

CLI args > env vars > config file. The script also reads
`~/.snowflake-mcp.json` if it exists (so you can share config with the
Snowflake MCP server).

Auth always uses `authenticator=externalbrowser` — the script opens a
browser window for SSO the first time and caches the token
automatically.

### `make_dummy_pdf.py`

Regenerate the 5-page dummy PDF at
`pdf/fy2024-tbk-investor-presentation.pdf`. The PDF is intentionally
small but contains enough structure (title page, financial table,
segment table, outlook, disclaimer) to exercise every Chunky ingestion
path: layout parsing, vision extraction, surgical-range replacement,
and chunk-metadata stamping.

**Run:**
```bash
pip install reportlab
python3 procedure/script/make_dummy_pdf.py
```

**Output:** `pdf/fy2024-tbk-investor-presentation.pdf` (~6 KB, 5 pages).

## The dummy PDF

`pdf/fy2024-tbk-investor-presentation.pdf` is a 5-page reportlab-generated
PDF used for end-to-end testing of the Chunky ingestion pipeline. It
contains:

| Page | Content |
|------|---------|
| 1 | Title page — "TBK Holdings, Inc. — Fiscal Year 2024 Investor Presentation" |
| 2 | Financial Highlights — 5-row financial table (Revenue, Gross Profit, etc.) |
| 3 | Segment Performance — 4-row segment table |
| 4 | FY2025 Outlook — body text on guidance and capital allocation |
| 5 | Disclaimer — forward-looking statements disclaimer |

The PDF is regenerated by `make_dummy_pdf.py` (deterministic — same
content every time). Commit the binary to the repo so test
environments don't need reportlab installed.

## End-to-end test flow

The intended end-to-end test flow is:

1. Regenerate the dummy PDF:
   ```bash
   python3 procedure/script/make_dummy_pdf.py
   ```

2. Upload it to a Snowflake stage:
   ```bash
   python3 procedure/script/upload_to_stage.py \
       --account $SNOWFLAKE_ACCOUNT --user $SNOWFLAKE_USER \
       --stage @DEV_DB.DNA.DOCS \
       --file procedure/script/pdf/fy2024-tbk-investor-presentation.pdf
   ```

3. Ingest it via the headless procedure:
   ```sql
   CALL chunky_chunks('ingest', OBJECT_CONSTRUCT(
       'db', 'DEV_DB', 'schema', 'DNA', 'table', 'TEST_CHUNKS',
       'stage_path', '@DEV_DB.DNA.DOCS',
       'file', 'fy2024-tbk-investor-presentation.pdf',
       'mode', 'OVERWRITE',
       'layout', true
   ));
   ```

4. Verify via `chunky_qa('search', ...)` or `chunky_qa('inspect', ...)`.

5. Revert if needed:
   ```sql
   CALL chunky_chunks('REVERT', OBJECT_CONSTRUCT(
       'db', 'DEV_DB', 'schema', 'DNA', 'table', 'TEST_CHUNKS',
       'timestamp_before', '<timestamp from step 3>'
   ));
   ```
